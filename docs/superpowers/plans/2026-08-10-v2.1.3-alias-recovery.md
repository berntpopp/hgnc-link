# HGNC Link v2.1.3 Alias Recovery Implementation Plan

> Historical record

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Apply the missing `2.1.3` GHCR alias to the already accepted HGNC Link v2.1.3 manifest, verify it, and remove the one-shot package-write workflow.

**Architecture:** A hard-coded `workflow_dispatch` job runs behind the existing `release` environment with only `contents: read` and `packages: write`. It verifies the immutable GitHub release, source alias digest, and OCI revision before copying identical manifest bytes, then a cleanup PR removes the workflow and its focused test.

**Tech Stack:** GitHub Actions YAML, pytest, PyYAML, GitHub CLI 2.96.0, ORAS 1.3.3, GHCR.

## Global Constraints

- Source revision: `0f318f20ba6ecf81682919718a416e018f84fe98`.
- Source alias: `sha-0f318f20ba6ecf81682919718a416e018f84fe98`.
- Release tag: `v2.1.3`; version alias: `2.1.3`.
- Accepted digest: `sha256:1b9f67c4d072dc84071fa65e72bebb8449df9935504bc4e7e9c398719eb6f31a`.
- No inputs, deployment commands, tag changes, image rebuilds, deletion paths, or scanner-policy changes.
- Recovery permissions are exactly `contents: read` and `packages: write`, guarded by environment `release`.
